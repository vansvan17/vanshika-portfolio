Board design

Hardware security module

6-layer PCB · STM32 · secure element

A board that keeps cryptographic keys where software can't get at them. An STM32 runs the show, a secure element holds the keys, tamper-detection circuitry watches for interference, and the sensitive parts sit on their own isolated power domains. The firmware checks its own signature at boot and only talks to the host over encrypted USB-C.

I did all of it: the schematic, routing the six layers, signal-integrity analysis and the firmware. Then I validated the design in simulation and on a hardware-in-the-loop test rig I built for it.

KiCad · 6 layers · STM32 · secure element · tamper detection · isolated power domains · hardware-backed key storage · secure boot · encrypted USB-C · FreeRTOS · C/C++ · signal-integrity analysis · hardware-in-the-loop tests
Built

Point-to-listen museum case

Museum exhibit · in progress

A display case you talk to by pointing. Hold a finger over an object for three seconds and its story plays in the headphones, while the screen under the glass glows beneath it. No buttons, no touchscreen: a camera above the case watches for your finger, and a passing hand does nothing.

Raspberry Pi 4 · Camera Module 3 NoIR · Python · OpenCV · background subtraction, fingertip = the point reaching farthest in · camera-to-TV calibration · ~11 fps at 960×540

FreeRTOS on a bare Raspberry Pi 4

Embedded · AArch64 · no Linux underneath

A real-time OS running straight on the Pi's hardware. The test images wouldn't boot until I traced it to how the image was laid out in memory: the Pi's firmware loads it at a fixed address and expects the start code right after a specific header. Fixed that, then added a log in RAM that survives reboots and cycle-counter timing for every task.

FreeRTOS · AArch64 · Pi 4 firmware and one-shot test boots · RAM log across reboots · cycle-counter instrumentation · L2 cache interference experiments
