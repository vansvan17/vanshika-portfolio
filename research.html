Keeping urgent jobs on time

Real-time scheduling · in progress

When a small computer runs a machine, some jobs can't be late: a motor controller has to answer on time, every time. I'm testing whether a different way of letting urgent jobs cut the line makes that timing steadier on a Raspberry Pi, compared with the tricks people already use.

FreeRTOS · AArch64 on Raspberry Pi 4 · preemption threshold vs temporary priority raise vs scheduler suspension · cycle-counter instrumentation for latency and missed deadlines · cache-interference runs under way

Editing a tree that won't sit still

Concurrent data structures · paper in progress

Picture a huge family tree or folder structure that lots of people change at once. DomLock is an existing way to let them work without stepping on each other. I'm studying how to apply many changes together in one batch, safely, while the shape of the tree itself keeps changing.

C++20 · DomLock · batched edge insert/delete on a DAG · prepare / validate / merge / apply deltas · runs at 1M–10M nodes · exact model and Python oracle as cross-checks

When the shortcut gets slow

Data structures · in progress

Lots of software keeps a running list and constantly asks "what's next?", like a server tracking which connections have timed out. The standard tool for this uses a clever shortcut that's usually faster. I found a pattern where it gets over five times slower, and it's the pattern those servers actually create. I'm working out exactly why.

C++20 · d-ary heap from scratch vs libc++ std::priority_queue · bottom-up (Floyd) pop 5.6× slower at 16M when pushes land near the top · settle depth ≈ log₂S / log₂N · algorithm and API effects measured separately
